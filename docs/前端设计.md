# 智能体课堂系统 · 前端设计

> 版本 v1.0（已确认）

## 1. 技术选型

| 项 | 选型 |
|---|---|
| 框架 | Vue 3 + Vite + TypeScript |
| UI 组件库 | Naive UI |
| 图标 | @vicons/ionicons5 |
| 状态管理 | Pinia |
| 路由 | Vue Router |
| 公式渲染 | KaTeX |
| 沙箱 | iframe（HTML5 `sandbox`）|
| 主题 | 浅色 + 深色切换 |

依赖安装（实施阶段）：

```bash
pnpm add naive-ui @vicons/ionicons5 katex
```

## 2. 设计令牌

- 中性色走 **slate 灰**，主强调色用 **青绿 teal**（避免"紫/靛蓝一切"的 AI 味）
- 浅色 / 深色各一套 token，通过 Naive UI `themeOverrides` + `darkTheme` 切换
- 主题切换：`useOsTheme` 跟随系统，用户手动切换后存 `localStorage`
- 圆角用一致刻度（Naive 默认 `6px` 层级，不做全局大圆角）；阴影极淡或不用
- 字体：系统字体栈；代码块等宽
- 标题层级 h1 → h3 不跳级

## 4. 路由

| 路径 | 页面 | 布局 |
|---|---|---|
| `/` | CourseListView（课程卡片 + 筛选）| MainLayout |
| `/course/:courseId/learn` | LearnView（slide/quiz/demo + 老师栏）| LearnLayout |
| `/create` | CreateView（Step 0 输入界面）| 独立（无 stepper）|
| `/preview/:courseId` | GenerateView（Step 1–4 生成流程）| GenerateLayout |

导航关系：

- 课程列表 `创建课程` 按钮 → `/create`，提交创建 draft 后 → `/preview/:courseId`
- `生成中` 课程卡 → `/preview/:courseId`（恢复 Step 3）；`已完成` → `/course/:courseId/learn`

## 5. 页面拆解

### 5.1 MainLayout（非移动端）

- **AppNavbar**：左 `Logo 图标 + "智能体课堂"`；右 `设置按钮`（gear 图标，`aria-label="设置"`）
- 点设置 → `NModal` 打开 **SettingsModal**，内 `NTabs`：
  - **用户信息**：username（可改）、email（可改）、头像（首字母占位）、修改密码（可选）
  - **外观**：跟随系统 / 亮色 / 暗色
- **模型配置**入口暂时屏蔽：平台统一在服务端配置文件提供全局模型，用户不自行配置（相关 store/组件保留待恢复）
- 内容区 → `router-view`

### 5.2 CourseListView（`/`）

- **CourseFilters**：`NInput`（名称模糊搜索）+ `NSelect`（学习状态：全部 / 未学习 / 正在学习 / 已完成）+ `NSelect`（归属：全部 / 我创建的 / 公共库）
- **CourseGrid**：`NSpin` 加载骨架 + 空态（`NEmpty` + 引导文案）+ 卡片网格
- **CourseCard**：标题、描述、状态徽标（语义色 + 文字，不只靠颜色）、"我创建的 / 公共库"标记、点击进入学习

### 5.3 LearnLayout / LearnView（`/course/:courseId/learn`）

- **LeaveButton**：左上返回箭头，回到 `/`
- **Stage（中间）** 按当前环节 `type` 渲染：
  - `slide`：页面元素（text / formula→KaTeX / shape / list）+ 讲解步骤，`下一步/上一步`，逐字显示 + 可选 TTS
  - `quiz`：题目列表一次性作答、提交后展示答案 + 逐项题解
  - `demo_3d`：主应用内以 Three.js（npm 引入）渲染 `section.content` 场景描述 JSON（见《3D演示数据结构.md》），不经 iframe；场景初始化/控制器由系统封装，前端解析 JSON 建 mesh/材质/灯光/相机，geometries 经 parentId 组成场景树（父变换级联带动子树，局部坐标语义）
  - `demo_function` / `demo_basic`：`iframe` 沙箱（`sandbox` 属性禁脚本外联；函数演示需在骨架预注入运行库，basic 可在线编辑代码）
- **SectionToolbar（中间与底部之间）**：`上一节 / 下一节` + 环节列表（可跳转），按 section `type` 切换 Stage
- **TeacherBar（底部）**：常驻显示当前 slide 步骤的**讲解旁白**（逐字 + 可选 TTS）；讨论模式激活期间切换为「讨论中… + 终止讨论」
- **ChatPanel**：问答抽屉壳（头部会话切换 + 消息历史 + 流式气泡 + 输入框）。头部提供「新对话」按钮与历史会话下拉（按最近活跃倒序，显示会话名/「新对话」），讨论流进行中禁用切换；发送即进入讨论模式（`discussion.start`），抽屉自动让位给讨论侧板；本面板可作为历史回看入口
- **DiscussionPanel（讨论侧板）**：讨论模式专属壳（见《讨论模式方案.md》§5/§8）。讨论激活时统一隐藏 StageToolbar / TeacherBar（移动端其底部 sheet 本就覆盖两者，PC 端隐藏以让出对话与舞台空间），侧板占位 420px；白板视图切换（`WhiteboardViewSwitch`，从 StageToolbar 抽出的复用组件）兜底挂顶栏，保证讨论中可切幻灯片/纯白板视图。移动端 sheet 高度统一为 `--learn-sheet-h`（46vh），讨论激活时舞台 `padding-bottom` 预留同高空间（`is-sheet-open`），slide/quiz/demo 在 sheet 上方的剩余区域居中，不再与 sheet 重合
  - 桌面端：固定占 `LearnView` 主区右侧 360px 布局位（**无遮罩浮层**，智能体在舞台中央的动作全程可见可交互）
  - 移动端：转底部 sheet（约占 46% 高、无遮罩），上半仍可见舞台动作
  - 消息复用 ChatMessages / ChatComposer；动作以标签流展示（动作本体由舞台元素叠加层与白板叠加层渲染）
- **白板叠加层**：WhiteboardLayer 支持 `overlayStrokes` 独立 prop——讨论中的 draw/clear_board 渲染在独立叠加画布，不进入正式回放流（`whiteboardStrokes` 派生保持纯净，order 编码位于 `stores/learnStrokes.ts` 纯函数）；终止讨论整层清空并恢复 entering 快照 `{sectionIndex, stepIndex}`。canvas 显示尺寸恒由 CSS `width/height: 100%` 充满容器（容器即 slide 逻辑尺寸 × scale），位图属性按 devicePixelRatio 超采样，保证高 DPI 下与 slide 坐标对齐

### 5.4 课程生成流程（`/create` + `/preview/:courseId`）

步骤流转：`输入知识点 → 生成大纲 → 确认大纲 → 生成内容 → 完成`

**GenerateLayout 头部**：左侧 `返回按钮`（回 `/`），中间 `GenerateStepper`（4 步：生成大纲 / 确认大纲 / 生成内容 / 完成），无 Logo/设置，聚焦流程。

#### Step 0 · 输入（`/create`）

- 居中布局：上方 `标题 + 副标题`（如「智能体课堂」+「描述你想学习的内容，AI 生成可互动课程」），配克制的 teal 特效（标题微渐变 / 柔和光晕 + 少量漂浮点缀，避免花哨）
- 中央 AI 对话框卡片：
  - `NUpload` 上传参考文档（多文件、10MB、PDF/Word/MD/txt，纯文本提取）→ 附件 chip 列表（可移除）
  - 文本输入 + 发送按钮
  - 工具条：模型下拉（选项来自 `GET /api/models`，即配置文件 `model.options`，加载后默认选中 `is_default` 项）、思考档位、参考文档上传
  - 配图开关 + 配图模型下拉（选项来自同一清单 `kind=image`，无兜底，开启配图时自动选中首个 image 模型）
- 提交 → 创建 draft 课程（回传所选 `model_key` / `image_model_key`）→ 跳 `/preview/:courseId`

#### Step 1 · 正在生成大纲（流式）

- 顶部状态文案：`正在分析知识点… → 正在生成大纲…`
- 流式列表：环节条目逐个出现（标题 + type 徽标 + 知识点标签），带淡入动画，SSE 驱动
- 完成后自动进入 Step 2

#### Step 2 · 确认大纲

- `OutlineItem` 列表，每项：`序号 + 标题 + type 徽标(slide/quiz/demo_3d/demo_function/demo_basic) + 知识点 tags + ↑↓ 按钮 + 删除按钮`
- 调序用上下移动按钮；删除需二次确认（`NPopconfirm`）；不可新增/改内容
- 全删空态提示
- 底部操作：`确认并开始生成`（主按钮）
- 注：「重新生成大纲」本期不做，后续版本考虑

#### Step 3 · 正在生成内容

- 进度列表：每环节 `pending / generating / done` 状态，当前生成中高亮，SSE 推送
- 明确提示 `可离开本页，生成将在后台继续`
- 返回按钮 → `/`（课程卡显示「生成中」徽标，可点击回来恢复进度）

#### Step 4 · 生成完成

- 成功图标 + `课程已生成完成`
- `进入学习` → `/course/:courseId/learn`；`返回课程库` → `/`

#### 步骤推导（前端）

`GenerateView` 读取 `course.status` + `outline` + `section` 推导 step：`completed`→4；`outline_confirmed/generating`→3；`outline.draft`→2；否则→1。

#### 后端对接点（实现时对齐）

- 创建 draft 课程接口、大纲生成 SSE、确认大纲、删除/调序接口、内容生成进度 SSE
- 「大纲生成中刷新恢复」需后端补状态（如 `outline_generating`）或前端重连

## 6. 状态管理（Pinia）

- `theme` / `auth` / `model-config` / `course` / `conversation` / `learn` / `discussion` / `generation` 等 store
- 均与后端接口解耦：先 mock，接口就位后替换；SSE 类接口（讨论流）走 `api/sse.ts` 原生 fetch 消费器，不经 axios。讨论流与问答历史已真接入（`api/discussion.ts`；事件 `{name,args}` 经 `mapAction` 映射为语义动作、未知/残参静默丢弃），进度上报与 demo 兜底仍为 mock
- `learn` store：导航锁定（`sectionLocked`）/ 暂停快照（`pausePlayback`）/ 恢复（`restorePlayback`）/ agent 跳转（`jumpToSection`）是讨论模式的唯一导航契约；白板笔画重放派生为 `stores/learnStrokes.ts` 纯函数
- `discussion` store：讨论模式状态机（进入快照 → SSE 严格队列消费（动作先落地后放行文本）→ end 后可追问 → stop 恢复快照）
