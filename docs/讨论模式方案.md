# 讨论模式 · 环节问答（智能体老师）设计

> 状态：后端已实施（service/agent/handler/路由/建表与单测落地），前端（§5 状态机与 SSE 消费）待实施。
>
> 本文档定义学习页「讨论模式」的完整设计：用户提问会中断课程讲解，进入讨论模式；智能体老师通过**带工具调用的 agent loop**一边流式回答一边输出讲解动作（切换幻灯片、划线、高亮、白板笔画等），由前端在页面实时渲染动作；用户点击「终止讨论」回到正常讲解流程。

## 1. 需求概述

- 提问**中断**课程讲解过程，切换到**讨论模式**；用户点击按钮终止讨论，回到正常讲解流程（还原到讨论前位置）。
- 智能体老师的回复 = 旁白文本 + **动作指令（LLM 工具调用）**，可交叠多轮。采用原生 OpenAI tool_calls 协议（可靠的结构化输出），不解析模型文本。
- **后端维护 agent loop**：一次提问一条 SSE，后端循环内收到 tool_calls 后**本地合成"success"结果**推进下一轮，不等待前端、不建立任何前端→后端的结果回传通道。
- **前端是动作执行器**：SSE 事件严格按序消费（队列），收到 action 先本地执行完毕再消费后续文本——SSE 顺序即语义顺序（动作先于承接旁白）。
- 会话为课程级问答会话（Conversation）：每用户每课程一条，跨环节共享，见《数据库设计.md》conversation/message 表。
- 复用课程生成的模型配置（`course.ModelConfigID`，为空回退默认配置）；用户提问时切换模型**首版不做**。
- 环节生成中禁问；可用时机对应环节 `done` 状态（沿用需求方案 3.4 节约定）。

## 2. 核心架构：单流 agent loop + 合成工具结果

```
POST /courses/:id/questions → 建立唯一一条 SSE

后端 agent loop（单 goroutine，轮次上限 8）：
  第 1 轮: system(老师人设+课程上下文+环节约束)
           + LRU 截断后的历史消息 + 用户问题
          → LLM(带 Tools 定义) 流式输出
          ├─ text delta        → SSE {type:"text", delta}
          └─ tool_calls 拼装完成 → 后端解析
                ① 落库 assistant(tool_call) 消息
                ② SSE {type:"action", action}
                ③ 本地合成 tool 结果 "success" + 落库 tool 消息
                ④ 同一条流继续下一轮 LLM 调用
  第 N 轮（纯文本收尾）→ 落库 assistant 文本消息
                        SSE {type:"end"} → 流关闭
```

要点：

| 决策点 | 结论 |
|---|---|
| 循环驱动 | 后端单 goroutine 循环；工具结果由后端合成（"success"），**无 tool-result HTTP 端点、无等待/唤醒/轮询** |
| SSE 生命周期 | 一次提问一条流直到收尾；无流重建状态机，无接缝竞态/幂等问题 |
| 顺序正确性 | SSE 有序 + 前端严格队列消费：action 先本地执行完再渲染后续 text；本地动作毫秒级，用户无感 |
| 上下文装配 | **服务端查库装配**：前端只传 `section_id`（提问来源，可空）；防伪造、载荷小 |
| 上下文粒度 | 整节 content + steps 全文归约为纯文本大纲（每元素/每步骤一行），并标注用户当前所处步骤（步骤索引为前端瞬时态，由前端随提问可信任地携带） |
| 历史截断 | 近似 token 窗口 LRU：system 恒定，从新到旧装载，字符数估算超阈值（约 16k tokens ≈ 48k 字符）丢最旧；首版不做摘要压缩 |
| 落库时序 | 逐条 message 落库：assistant(tool_call)、tool 合成结果、assistant 文本，随 loop 推进即时落库 |
| 并发约束 | 生成中禁问（前端置灰 + 后端校验课程无 generating 环节）；LLM 调用绑定请求 context，断连时 loop 随请求取消，已落库消息保留 |

### 边界情况

1. **轮次上限**：loop 上限 8 轮，超限注入"请直接用文本回答收尾"的系统约束强制收尾，防工具死循环。
2. **动作失败无回传**：模型幻觉 element_id / 前端执行失败时，前端静默降级忽略该动作，旁白照讲；system 提示强调"只引用上下文中给出的元素 id"。
3. **断线**：单流中断后 loop 随请求 context 取消；不做中途续播，用户重新提问续走。

## 3. 工具集（LLM 可调用）

## 4. LLM 适配器扩展（通用能力）

现状：`model/llm/openai.go` 仅纯文本 `ChatStream`，不支持 tool use。

改动（**通用扩展 chat 流协议**，不做问答专用旁路，后续其他 agent 可复用）：

- `model.ChatMessage` 增加 `tool_calls` 字段（assistant 发起）与 tool 角色消息支持。
- `model.ChatRequest` 增加 `Tools`（OpenAI tools 格式）。
- `ChatStream` 解析流式 `tool_calls` 增量（index 对齐、参数累加拼装），拼装完成经回调上抛。
- `model.Registry` 路由不变。
- 首版只承诺 OpenAI 兼容协议；百炼专属协议 tool use 适配后续跟进。

## 5. 讨论模式状态机（学习页）

存续于 learn store，新增 `discussionMode` 状态：

- **进入**：提问触发（生成期间禁入）。暂停讲解推进；快照 `{sectionIndex, stepIndex}`；建立**叠加层**（overlay state），讨论动作全部渲染在叠加层，**不写入正式讲解的白板重放流**（`whiteboardStrokes` 的 `order = sectionIndex*1000 + stepIndex` 累积逻辑不被污染）。
- **讨论中**：action 事件驱动叠加层执行；导航锁定（禁止手动切环节/切步骤，只能被 `jump_to_section` 动作带走）；仅允许白板视图切换。jump 之后当前环节上下文以此为准（后续动作的目标环节）。
- **退出（终止讨论按钮）**：清除叠加层 → 恢复快照位置 → 继续正式讲解。
- **刷新/重进**：若讨论未终止，按消息历史**重放末态**恢复叠加层（每个元素只取最后一次强调动作；遇 `clear_board` 后只重放其后的 `draw`）。
- **分环节约束**：
  - slide：全部工具可用。
  - quiz：可进讨论；**防作弊是上下文装配层的硬约束而非提示词约定**——service 装配 quiz 上下文时直接剔除题目 answer / 解释字段，只保留题面与选项（prompt 层约束只作补充，对诱导式提问抵抗力不足）。
  - demo：可进讨论，但仅可用 `jump_to_section` + 纯文本（iframe 沙箱，幻灯片动作无处安放）。

## 6. 消息落库格式

message 表按《数据库设计.md》：`content` jsonb、role 划分，随 loop 推进逐条落库：

| role | content 结构 |
|---|---|
| `user` | 文本 |
| `assistant`| `{text}` 或 `{tool_calls:[{id,name,arguments}...]}`（带文本时为纯文本收尾轮）|
| `tool` | `{tool_call_id, name, result}`（后端合成的 "success"）|

- ChatPanel 只渲染有文本的 assistant 消息；动作重放按 §5 末态规则。
- service 组装 LLM 上下文时严格还原消息序列（assistant tool_call ↔ tool 成对），保证多轮工具对话可继续。

## 7. 提示词约定

- 新增 `prompts/discussion.md`（老师人设 + 工具使用规则 + 上下文注入规则 + quiz 防露答案的补充指令），经 `go:embed` 引入（项目铁律）。quiz 防作弊的主防线在上下文装配硬剔除（§5），提示词约束仅作补充。

## 8. API 设计

| 方法 | 路径 | 说明 |
|---|---|---|
| POST | `/api/courses/:id/questions` | 提问，SSE 流式返回 `{type:"text",delta}` / `{type:"action",action}` / `{type:"end"}` 事件，流内完成整个 agent loop |
| GET | `/api/courses/:id/conversation` | 拉取课程级问答历史（结构化消息，前端按末态规则重放动作）|

均挂 auth + 用户身份中间件；轮次上限、生成中禁问等校验在 service 层。SSE 事件为统一类型化封装：`{type:"text",delta:string}`、`{type:"action",action:ActionPayload}`、`{type:"end"}`。

## 10. 首版明确不做

- 百炼专属协议 tool use 适配
- 用户提问时切换问答模型
- 老消息摘要压缩 / 向量检索 RAG
- 讨论中自由翻页后回归原位
- 并发提问限流（沿用「生成中禁问」）
- 工具调用结果的真实回传与执行失败纠错（后端一律合成 success，前端静默降级）
- 断线中途续播（重新提问续走）
